# 上线前调研手册

写页面之前先花一小时查一圈：有没有人做过、网上怎么讨论的、坑在哪、为什么还轮得到你。
这一步的目的是**证伪，不是证实**。它能帮用户便宜地砍掉一个烂想法，
但查出来一片大好也不代表该做——落地页才是真正的测试，调研只负责拦住明显的坑。

**时间盒：30 到 60 分钟。** 查到第二个小时还下不了结论，说明调研已经变成拖延，强行收尾。

---

## 一条核心原则

**搜不到竞品不等于有需求。** 更常见的解释是需求是伪的，或者前人试过死掉了。
反过来，搜到一堆竞品也不是坏消息——竞品是别人替你花钱验证过的市场。

要找的不是「空白市场」，是**「有人做但用户还在骂」的市场**。

还有一条职业操守：你的职责是把证据摆出来，**包括用户不想听的那种**。
查完一片空白还硬夸「蓝海机会」是失职，不是情商。

---

## 要回答的五个问题

### 1. 有没有现成方案？

按产品形态挑 2 到 3 个地方搜，不用全跑一遍：

| 类型 | 去哪 |
| --- | --- |
| 产品目录 | Product Hunt、AlternativeTo；B2B 加 G2 / Capterra |
| 移动端 | App Store / Google Play 直接搜使用场景 |
| 开发者工具 | GitHub（搜 topic 和 README）、npm / PyPI |
| 中文市场 | 微信小程序搜一搜、知乎「XX 工具推荐」、小红书 |

产出一张竞品表，**最多 5 个**，每个记四样：名字、定价、主打卖点、用户骂得最凶的一点。
定价拿不到就记「没公开」，那本身也是信息。

### 2. 网上有没有真实讨论？

去用户聚集的地方搜**自发的抱怨**，不是搜产品：

| 平台 | 技巧 |
| --- | --- |
| Reddit | 搜对口 subreddit，用 `"is there a tool"` `"why is there no"` 这类句式 |
| Hacker News | 用 hn.algolia.com 搜历史帖，能看到跨年份的讨论 |
| 知乎 / V2EX / 即刻 | 「求推荐」「有没有什么软件」「受不了」+ 场景关键词 |
| Twitter/X / 小红书 | 搜场景吐槽，看真实用语（这些原话后面写文案直接用） |

常用搜索词模板：

- 英文：`<问题场景> tool`、`alternative to <竞品>`、`<竞品> sucks`、`"how do you handle <场景>"`
- 中文：「<场景> 怎么解决」「<竞品> 替代」「<场景> 太麻烦了」

**收集 3 到 5 条抱怨原话，带链接。** 这些原话是全流程最值钱的素材：
痛点区文案直接用它们改写（见 `copy-playbook.md` 问题区），比你自己编的准十倍。

### 3. 痛点是真的吗？

| 真痛点长这样 | 假痛点长这样 |
| --- | --- |
| 抱怨里带具体数字：每周耗几小时、每月多花多少钱 | 被问到才说「确实有点烦」，没人主动发帖 |
| 正在用一个很难受的 workaround（Excel + 手动 + 求人）而且一直在用 | 抱怨完接一句「不过现在这样也还行」 |
| 同样的抱怨跨社区、跨年份反复出现 | 讨论集中在同一周（蹭热点），之后没人再提 |
| 有人在帖子里主动问「收费吗，我愿意付」 | 一提到付费就散场 |

### 4. 解决起来有没有坑？

- 读竞品的**一二星差评**（G2 / Capterra / App Store）：用户骂的地方就是难做对的地方
- 搜前人尸体：Indie Hackers 的 postmortem 版块、Google `<方向> shut down / postmortem`、
  中文搜「XX 为什么做不起来」
- 几个前人死在**同一个地方**（拿不到数据、接不上渠道、获客太贵），那就是硬墙，
  要问用户一句：你有什么独特的绕行方式吗？

### 5. 为什么还没被解决掉？

这是最重要的一问。市面上没有好方案，一定有个原因，你要找到它并判断它会不会也杀死这个想法：

| 可能的解释 | 怎么识别 | 对用户意味着什么 |
| --- | --- | --- |
| 市场太小，养不活公司 | 竞品全是 side project，没有拿融资的玩家 | 公司做不了 ≠ 一个人做不了。问清他要的是生意还是小产品 |
| 获客比客单价贵 | 竞品功能都还行，但谁都没做起来 | 危险信号，他跑落地页流量时会撞上同一堵墙 |
| 巨头顺手免费做了 80% | 讨论区常见「用 Notion / Excel / 微信也能凑合」 | 只能服务剩下 20% 疼到愿意付钱的人，文案要直接冲他们写 |
| 技术 / 数据 / 牌照是硬墙 | 前人 postmortem 全死在同一步 | 没有独特绕行方式就该砍 |
| 人人都骂但没人付钱 | 抱怨一大片，竞品的付费版无人问津 | 最常见的伪需求形态。落地页必须挂价格测 |
| 其实已被解决，只是搜法不对 | 换个关键词就搜到成熟产品 | 问题不在产品在获客；或者直接用现成的，别做 |

## 产出：一页 research brief

调研结果整理成固定结构发在对话里，别写成长文：

```
## <想法> 调研 brief

**竞品**（最多 5 个）
| 名字 | 定价 | 主打 | 用户最大的槽点 |

**真实抱怨**（3 到 5 条原话，带链接）

**坑**：解决这个问题的已知难点，前人死在哪

**为什么还没被解决**：上表哪一条，证据是什么

**结论**：照做 / 换切角 / 别做
```

### 结论怎么下

三选一，必须选，不许「仅供参考」：

- **照做**：有自发的真实抱怨，竞品有明显空隙或差评集中在用户能做好的点上。
  直接进下一步，把抱怨原话和竞品定价带上
- **换切角**：痛点是真的，但原来的切法撞上硬墙或巨头。给出具体的新切角
  （缩小人群、换收费模式、换场景），跟用户确认后按新切角走后面的流程
- **别做**：搜不到任何自发抱怨、前人死因绕不开、或是典型伪需求。
  把证据摆出来直说，替他省下两周。两周换一个假设，一年能试 26 个

### 查到的东西怎么喂给后面的步骤

| 调研产出 | 用在哪 |
| --- | --- |
| 抱怨原话 | 痛点区三条文案的底稿，headline 的用词 |
| 竞品定价 | 定价锚点：`PRICE_NOTE` 里写「比 XX 便宜一半」这类对比 |
| 竞品差评 | 差异化角度：对方做砸的那件事就是 subhead 的切入点 |
| 竞品名字 | 起名时避开，别撞车也别蹭 |
